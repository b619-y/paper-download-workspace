# 系统架构

```text
研究问题
  ↓
检索式 Agent（3 套检索策略 + 数据库翻译 + 实测）
  ↓
检索 Agent（9 个 API，全分页，原始响应与完整性清单）
  ↓
去重 Agent（DOI；否则题名+年份；保留来源合并记录）
  ↓
论文筛选 Agent（ASReview，题名+摘要，人工少量标注后主动学习排序）
  ↓
标准复核 Agent（可选，明确标准 + Luna 解释，保留 uncertain）
  ↓
下载 Agent（公开源 / 出版社 / 已授权机构访问，身份与完整性核验）
  ↓
全文筛选 Agent（PaperQA2 解析 + 独立 embedding/检索 + Luna）
  ↓
原 PDF / 表格 / 图片复核 → 数据提取 Agent
```

## 模型职责

- ASReview ELAS U4：题名和摘要的词法主动学习排序，TF-IDF + SVM，不需要 GPU。
- Embedding：独立部署、独立版本和索引；不由 Luna 代替。主机与模型待资源盘点后写入 `config/embedding.example.json` 的本地副本。
- Codex Luna：通过 Codex CLI 调用，只做标准判断、候选证据解释和 JSON 输出，不提供 embedding。
- PaperQA2：负责 PDF 解析和全文证据流程；所有引用仍要做原文子串、页码及文件身份核验。

## 下载清单不是单一分数

检索结果先完整保存并去重；ASReview 的相关性排序用于决定“先看哪些”。最终进入下载清单的是人工/模型依据明确标准给出的 `download` 和高召回任务中的 `uncertain`，不是简单按某个分数阈值自动删掉其余记录。

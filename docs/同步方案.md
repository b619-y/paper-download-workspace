# Mac、capg 与 GitHub 同步方案

## 代码与配置

GitHub 私有仓库是代码、合同、提示词和模板的中枢。Mac 与 capg 都只通过 Git 拉取/推送这些文件。密钥、PDF、索引、项目数据库不提交。

## 运行数据

避免双向覆盖，固定两条方向：

1. Mac → capg：已核验 PDF、检索导出和筛选清单；
2. capg → Mac：ASReview 导出、PaperQA/Luna 结果和计算日志。

`scripts/sync_runtime.sh` 默认只预览；加 `--apply` 才执行。它使用 `rsync --ignore-existing`，若目标已有同名文件则保留目标并报告差异，不静默覆盖。

工作流指针和 `runtime/tasks/` 由 Mac 协调端维护。每次让 capg Agent 接管前，先预览并单向同步：

```bash
scripts/sync_runtime.sh push-workflow
scripts/sync_runtime.sh push-workflow --apply
```

`push-workflow` 可更新 capg 上的旧状态，但会把被替换的远端版本备份到 `runtime/conflict_backups/workflow-state/`。capg 计算 Agent 不直接改写 `runtime/tasks/` 或 `ACTIVE_TASK.json`；它们把结果写入 `runtime/results/`，再由 Mac 端 `pull-results` 拉回并验收合并。

## GitHub 边界

- 允许：源码、合同、角色说明、空模板、非敏感示例。
- 禁止：论文全文、补充材料、Cookie、Token、API key、ASReview 项目文件、PaperQA 索引、真实研究数据。

# 部署验收（2026-10-13）

## 计算端

- PaperQA 依赖：`paper-qa==2026.8.12`，Python 3.11；`pip check`、导入和可选 `paperqa-pypdf` PDF 解析通过。工作区的 `paperqa_luna.py` 是自有 PaperQA-style 适配器，并未验收或调用 PaperQA2 query/agent engine。
- ASReview：`asreview==3.0.8`；本地回环健康检查通过。实际端口与数据目录由部署环境变量/本地配置提供，不写入公共仓库。
- Codex CLI：`gpt-6-luna` 被当前 ChatGPT 登录拒绝；`gpt-5.6-luna` 可用并通过 JSON Schema 输出。
- Embedding：通过 `$PAPER_EMBEDDING_BASE_URL` 指向的受限端点完成健康检查。

## Embedding 服务端

- 模型：`BAAI/bge-m3`，FP16，输出 1024 维向量。
- 网络：只通过部署方配置的受限端点访问，不在公共文档披露主机、端口、GPU 编号、容器名或内部路径。
- 合成中英文请求返回预期数量与维度的向量。

## 端到端验收

合成 PDF 包含一条优化方法和一条 F1 改进。流水线完成：

1. `paperqa-pypdf` 可选组件把合成 PDF 解析为持久化、带哈希的文本；
2. BGE-M3 检索候选段落；
3. `gpt-5.6-luna` 输出 `include` 和结构化证据；
4. `exact_quote` 与候选原文逐字子串匹配通过。

验收文件位于计算端运行区 `runtime/results/smoke/evidence-embedding-luna.json`，不进入 GitHub。该冒烟测试只证明组件可运行，不代表任何真实论文获准外传，也不代表候选判断已自动通过人工验收。
